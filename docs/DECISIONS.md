# Decisions

One line per decision, with the reason. Game rules and specs live in
`PLATFORM_EXPANSION_BRIEF.md`.

| Date | Area | Decision | Reason |
|---|---|---|---|
| 2026-11-06 | Seats | Seats are 8 stable slots assigned to the lowest free index on join; a seat is only reused after its owner is reaped or removed. | A player's colour/shape must not swap between games or when someone else leaves. |
| 2026-11-06 | Seats | Seat identity is `{ index, color, shape, emoji }`, with both a shape name and a mono glyph. | Colour alone is not accessible; the shape works on every display and in the canvas renderer. |
| 2026-11-06 | Names | Join names are trimmed, then truncated to 12 characters, then deduplicated as `Ana`, `Ana 2`, `Ana 3`. | Matches the brief; deduplication after truncation stops names that only differ past 12 characters from colliding. |
| 2026-11-06 | Names | The numeric dedupe suffix counts toward the 12-character cap, so a 12-character name shortens its base before the suffix. | Keeps every name inside the same cap without a second, longer limit. |
| 2026-11-06 | Rooms | The lobby always has 8 seats; a game's own `maxPlayers` is only checked when starting it. | Phase 2 raises the platform, not every game; small games stay greyed out until their per-game task widens them. |
| 2026-11-06 | Registry | `shared/game-catalog.ts` is the single source for display name, enabled, kind, ideal range, minutes, dropout policy, content packs and `scale()`. `manifest.json` keeps id/name/hard limits/copy; the loader merges the catalog over it. | The lobby, start gate and Rumble must not disagree; hard ranges mirror the JSON and a test fails on drift. |
| 2026-11-06 | Registry | Kind is the action players perform: writing (bluff, writevote, splitroom, survive, frankenanswers, bracket, dumbinventions), drawing (drawful, sloganshirts), deduction (stowaway, fakin), trivia (quiz, percentile), skill (archery, arena, racing), party (mostlikely, blather, slideroulette, mindmeld), cards (poker). | The Rumble resolver substitutes within a kind, so kind must describe the play, not the theme. |
| 2026-11-06 | Registry | Drop-out policy: `continue` for timer-driven games, `void-round` when the round needs that role (artist, presenter, writer, Stowaway, Faker, guesser), `pause` when a turn has no timer (archery aim), `forfeit` when leaving decides a duel/match (bracket, guess who, spin war, word chain, last seat). | Each game declares how a missing player affects its round; the platform does not guess. |
| 2026-11-06 | Registry | `scale()` reports today's implemented rounds in both modes; `minutes.rumble` uses the brief's shorter Rumble target. Timers are whole seconds. | Phase 2 records reality; per-game tasks split standalone from rumble. |
| 2026-11-06 | Registry | `enabled: false` is a registry flag, never a delete. Unknown or uncatalogued ids count as disabled. | Games leave the lobby without leaving the tree, and a half-registered game cannot ship. |
| 2026-11-06 | Scoring | Reserved: `f(N) = min(1, 3/(N-1))` and `rankPoints(rank,N) = round(100*(N-rank)/(N-1))` live in the shared scoring module; fixed payouts never scale. | Brief 3.3; 3-4 player results must stay identical. |
| 2026-11-06 | Scoring | `shared/scoring.ts` rounds half-up, gives a tie block the competition rank of its first position with each tied player receiving the rounded average of the block's rank points, breaks equal raws by id, and returns factor 1 / the base payout / 100 points for `N < 2`. | Brief 3.3 says `round()` and "share the average" without pinning the integer or tie order; games and the round-sanity test need one exact, deterministic rule. |
| 2026-11-06 | Voting | TV vote lists use one column for 1-6 options (48-72px type at 1080p) and two columns with A/B/C badges for 7+ (36-56px); 10+ keeps two columns and extends letters to AA, AB … so games can page without recomputing. Phone choices keep a 56px minimum tap target and switch to a two-column badge grid at 7+ options. | Brief 3.5; 48px is the kit's large-type floor at 3 metres, 28px two-column floor matches body text, and 56px stays above 48dp at 1.5x phone text. |
| 2026-11-06 | Presence | `Player.presence` is the authoritative table status (`active`, `away`, `left`); `connected` stays for compatibility with older clients and game code. A socket close marks `away` immediately and keeps the existing 30-second rejoin grace; a token rejoin returns the seat to `active`. An explicit `leave` marks `left`, keeps the room row and this game's score, and the seat is only dropped by the reap path or the next game start. | The TV and phones need one field to render, and a deliberate leave must not look like a network drop. |
| 2026-11-06 | Spectators | A brand-new phone that joins while `room.status === "playing"` takes a real seat with `spectator: true` (counted toward the 8-seat ceiling) instead of `GAME_IN_PROGRESS`; it receives the TV screen plus a `{ spectator: true }` controller, its game inputs are dropped, and it is promoted to a normal seat when the room returns to the lobby. A brand-new join during a Rumble still gets `SESSION_IN_PROGRESS`. Games receive only non-spectator players in `onStart`. | Brief 3.6; late joiners get to watch and are seated for the next game without mutating per-game state that was sized at start. |
| 2026-11-06 | Reactions | Exactly eight emoji ids live in `shared/reactions.ts`; the server validates the id, accepts reactions from spectators but not away/left players, and allows one per player per 2000 ms on the server clock, returning `REACTION_RATE_LIMITED` inside the window. The broadcast carries `{ playerId, name, seat, id, emoji }` to the TV and phones. | Brief 3.8; one fixed palette keeps the TV and phone bars identical, and the server clock stops a throttled client from double-firing. |
| 2026-11-06 | Pause | A running game whose connected non-spectator players fall below its manifest `minPlayers` pauses once: `RoomState.pause` becomes `{ reason: "players", startedAt, until }` with `until = startedAt + 60 s` (`DROPOUT_PAUSE_MS`), `onTick` is skipped, the paused wall time is dropped, and no new frames are sent. Enough players reconnecting clear the pause at once; after `until` the pause persists until the host chooses. The host endpoints are `POST /pause` (Wait: `until = now + 60 s`; 409 unless a game is running, a no-op when already running and not paused), `POST /resume` (409 `BELOW_MINIMUM` while short), and the existing `POST /end-game`, which clears the pause and, in a Rumble, aborts the round back to the next-game vote. The first phone receives the host token alongside the screen. | Brief 3.6; a frozen game must not lose round time while phones swap batteries, and a deadline alone cannot decide for a host who may prefer to wait. |
| 2026-11-06 | Results | A game's optional `results()` is used only when it covers every player exactly once with finite raws, finite ranks and finite stats. Otherwise `extractGameResult` derives standings from the screen tables games already publish (`scores`/`players`/`racers`, plus a winner-only row), ranks them with `rankWithTies`, lifts a declared winner to first for ranking while keeping its real raw, and negates raw for golf strokes and darts remaining score before ranking so the real raw values survive. Per-player stats use `<playerId>:<statKey>` (reversed keys are also accepted), and `normaliseGameResult` dedupes, coerces finite numbers and fills missing players with raw 0. | Current games publish only screen state; the fallback records raw scores and stats today without editing every game, while one normalisation gate keeps NaN, duplicate seats and unknown ids out of Rumble data. |
| 2026-11-06 | Awards | The seven briefed awards map to ordered stat-key aliases: Best Liar (`votesFooled`/`bluffsBelieved`/`fools`), Sharpest Eye (`correctAccusations`/`correctVotes`/`correctCalls`), Fastest Fingers (lowest `averageAnswerMs`/`avgAnswerMs`/`answerMs`/`fastestMs`), Crowd Favourite (`votesReceived`/`audienceVotes`/`reactionsReceived`), Cold-Blooded (`biggestPot`/`betrayals`/`eliminations`/`kills`), Comeback Kid (biggest first-to-last round place gain, falling back to `rankImprovement`/`placesGained`), Master of Disguise (`roundsUndetected`/`timesUndetected`/`roundsSurvived`). Awards run in brief order, cap at six, and break ties by player name then id; no stats means no awards and the existing `trophies` stay independent. | Brief 3.7 leaves stat names to each game; one mapping stops games inventing award names, and the cap plus name tie-break keeps the finale readable and deterministic. |
| 2026-11-06 | Interlude | The TV shows a 15-second between-game card after the existing 7-second results hold: standings with up/down/new arrows, the next game's name, one-line rule and live non-spectator player count, a visible countdown and a host Skip button that just dismisses to the lobby or Rumble voting panel. It is skipped for the Rumble finale, for a host-aborted game (no final standings) and when no active players remain. | Brief 3.8 asks for 15-20 s; 15 s keeps the next game moving, the finale podium is its own moment, and an empty room should see the join QR instead of a card. |
| 2026-11-06 | Ticker | The persistent in-game score ticker is a compact card in the bottom-right corner: one row per seat (colour + glyph badge, name, score), sourced from whichever of `players`/`scores`/`racers` the running game publishes. Scores count up over 700 ms, the leader gets an amber marker, and a real leader change flashes that row once for 900 ms. | Bottom-right is the least-used corner of the current renderers; a compact card keeps every avatar and score visible without shrinking the play area, and the leader marker never relies on colour alone. |
| 2026-11-06 | Captions | A screen-state `caption` draws large for 3000 ms, and a `reveal` (string or array) flashes a band for 1200 ms. Captions come from the fixed `shared/interlude.ts` bank filled only with a public name and count, so no game can leak a secret through one. Both are suppressed on a finished game and both respect `prefers-reduced-motion`. | Brief 3.8 wants short reveal lines and a show that keeps moving; 3 s reads at 3 metres without covering the next beat, and a fixed bank makes caption privacy a property of the module rather than each game. |
| 2026-11-06 | Sound/TTS | Sound cues (`reveal`, `vote`, `win`, `tick`, `whoosh`) are synthesised with a few WebAudio oscillators in `client/screen/sound.ts`, so the repository ships no audio assets and nothing needs a licence. The frame loop plays a screen state's `sound` cues only when their JSON signature changes, and a new `caption` adds one `reveal` cue if the game did not publish one. Speech uses the browser's `speechSynthesis`, cancels the previous line and speaks only a changed, non-empty `announce` string. Both preferences live in `localStorage` (`tbrn_screen_sound`, `tbrn_screen_speech`): sound defaults on, speech defaults on but is forced off when `speechSynthesis` is missing, and the settings gear is keyboard operable. The toggle only grants permission; the game's own text is the only thing spoken. | Brief 3.8 asks for sound and turn announcements with a mute toggle; an oscillator synth avoids asset licensing and load time, dedupe keeps a 60 fps screen from replaying a cue every frame, and forcing speech off without a synthesiser stops a dead toggle from pretending to work. |
| 2026-11-06 | Bluff packs | Bluff takes a host option `contentPack: "facts" \| "dictionary"` (default `"facts"`). Both packs live in `games/bluff/content/*.json` and load once at module init. Dictionary mode uses the word as the prompt and its definition as the real answer; Dictionarium keeps its own code and stays disabled. | Brief 4 merges Dictionarium into Bluff as the Dictionary pack without deleting the retired game, and keeping the prompts out of TypeScript lets the pack grow without touching flow code. |
| 2026-11-06 | Bluff rounds | Bluff's catalog `scale()` reports standalone 6 rounds and Rumble 4 rounds, dropping to 3 in Rumble at N >= 7; write/vote/reveal timers stay 30/20/6 seconds. The standalone game start continues to run 6 rounds until the Rumble passes a mode or round count into `onStart`. | Brief 4 gives 6 / 4 (3 at N >= 7); the catalog owns the target, while Phase 5's Rumble plumbing is what will select the shorter count at start. |
| 2026-11-06 | Write & Vote rounds | Write & Vote is 3-8 players. Its catalog `scale()` reports standalone 5 rounds and Rumble 3 rounds at every count; write/vote/reveal timers stay 45/20/6 seconds. The standalone game start continues to run 5 rounds until the Rumble passes a mode or round count into `onStart`. | Brief 4 gives 5 / 3; the catalog owns the target, while Phase 5's Rumble plumbing is what will select the shorter count at start. |
| 2026-11-06 | Write & Vote votes | A player may change their vote until every player has voted or the server clock ends. `canChangeVote` from `shared/vote-options.ts` is exposed on the voting controller state and enforced on input; a later pick overwrites the earlier one, so there is still exactly one vote per player. The ballot closes the moment the last player votes. | Brief 3.5 asks for changeable votes; reusing the shared predicate keeps the phone and server from disagreeing, and the reveal can still be exact because the ballot locks before scoring. |
| 2026-11-06 | Write & Vote reveal | The TV switches to the two-column letter grid from six answers, not the shared layout's seven-option threshold. The letters come from `voteLayout` and the type floor is the shared readable minimum at both 1080p and 720p. The reveal caption names the top vote-getter and their vote count from the fixed caption bank; no answer text, author or tally reaches the TV before the reveal. | Brief 4 says "at 6+ answers use the grid layout"; six answers in two columns still leaves a large readable cell, while the shared threshold stays unchanged for other games. |
| 2026-11-06 | Split the Room rounds | Split the Room is 3-8 players. Standalone rounds are `Math.max(4, Math.min(N, 8))`, not a literal `rounds = N`, so N=3 and N=4 still play four rounds; Rumble rounds are `Math.min(N, 4)`. Write/vote/reveal timers stay 45/25/8 seconds. | The human requires 3- and 4-player totals to stay identical to today's fixed four-round game; a literal N would give N=3 only three rounds and change them. |
| 2026-11-06 | Split the Room rotation | The writer is `round % N` over the seat order, so every player writes exactly once per cycle and each player writes once at 5-8 players (where standalone rounds equal N). At N=3 and N=4 the first seats write a second time in the extra round. The order is not shuffled. | A deterministic rotation preserves the 3-4 player scenario/writer pairing and therefore the required identical totals, while still meeting "the writer rotates" and one write per player at 5-8. |
| 2026-11-06 | Split the Room scoring | Writer payout stays `1000 - \|yes - no\| * (1000 / voters)` rounded half up, with `voters` = non-writers; each minority voter gets a fixed 150. No `f(N)` is applied because the `voters` denominator already scales. `results()` reports standings plus `splitScore` and `minorityCalls` per player. | Brief 4 fixes this formula and says it already scales; adding `f(N)` would double-scale and break the 3-4 parity requirement. |
| 2026-11-06 | Survive range | Survive the Internet is 3-6 players, ideal 4-6. Catalog `scale()` reports standalone 3 rounds and Rumble 2 rounds at every count; answer/twist/vote/reveal timers stay 45/40/25/9 seconds. The standalone game start continues to run 3 rounds until the Rumble passes a mode or round count into `onStart`. | Brief 4 gives 3-6 / 4-6 and 3 / 2 rounds; the catalog owns the target while Phase 5's Rumble plumbing selects the shorter count at start. |
| 2026-11-06 | Survive pairings | Each round's `pairing[writer] = quoted` is a secure-random derangement (rejection sampling over `secureShuffle`, with a secure N-cycle fallback), so every player writes exactly one headline for someone else and nobody quotes themselves. The ballot has one slot per pairing; a voter's options exclude the pairing they wrote and the pairing that quotes them, so at N players every voter has N-2 valid options (1 at 3 players, 4 at 6). Votes are one per player and may be changed until the ballot closes. | Brief 4 needs every answer twisted by someone else and no vote for your own pairing; N-2 options is non-zero at the 3-player minimum, and a derangement is the exact combinatorial object for "everybody twists someone else". |
| 2026-11-06 | Survive scoring | Each vote pays `scalePayout(700, N)` to the headline writer and `scalePayout(300, N)` to the quoted player (700/300 exactly at 3-4, 525/225 at 5, 420/180 at 6). Because one player holds both a writer seat and a quoted seat, a stacked ballot can pay them twice; the game caps that player's total round gain at `MAX_ROUND_SCORE` (1500) so brief 3.3's round sanity bound still holds. `results()` reports standings plus `votesReceived` (writer votes) and `quotedVotes` (votes for a player's answer). | Brief 4 fixes the per-vote split and 3.3 requires the 1500 bound; without the cap the two roles stack past 1500 from 4 players upward (e.g. 4 eligible votes at 6 pay 1680 to the writer alone), so the cap is the smallest rule that satisfies both. |
| 2026-11-06 | Frankenanswers range | Frankenanswers is 3-6 players, ideal 4-6. Catalog `scale()` reports standalone 3 rounds and Rumble 2 at every count, with the 6-foreign-chip + 4-connector pool unchanged; the standalone start now runs 3 rounds. | Brief 4 gives 3-6 / 4-6 and 3 / 2 rounds, and caps the game at 6 because more answers are too much to read. |
| 2026-11-06 | Frankenanswers scoring | Each vote pays `scalePayout(1000, N)` to the answer's author and each chip used by a winning answer pays its author `scalePayout(100, N)` (1000/100 exactly at 3-4, 750/75 at 5, 600/60 at 6); chip credit stays on winning answers only, as today. One player's total round gain is capped at `MAX_ROUND_SCORE` only at N >= 5. `results()` reports standings plus `votesReceived` and `chipsBorrowed`. | Brief 4 fixes the payouts and 3.3 asks for a 1500 bound, but the human's hard rule keeps 3-4 totals identical to the old implementation, where two votes at N=3 pay 2000. 3-4 parity therefore takes precedence over the literal bound, and the cap starts at five players, where the stacked formula pays 3000. |
| 2026-11-06 | Frankenanswers reveal | The TV switches to the two-column letter grid from six composed answers, using `voteLayout(..., { minColumns: 2 })` plus a screen-state `optionColumns` hint; the two-column 36px type floor applies. The reveal caption names the most-voted answer's author, never the composed text. | Six long composed answers are already too dense for one readable column at 3 metres, while the shared seven-option threshold stays unchanged for every other game. |
| 2026-11-06 | Dumb Inventions range | Dumb Inventions is 3-6 players, ideal 4-6. Catalog `scale()` reports standalone 3 rounds and Rumble 2 at every count, with invent/vote/reveal timers unchanged at 90/25/9 seconds; the standalone start now runs 3 rounds. The round cap is 6 because every pitch needs a vote slot and six rows is the readable maximum. | Brief 4 gives 3-6 / 4-6 and 3 / 2 rounds; Phase 5's Rumble plumbing will select the shorter count at start. |
| 2026-11-06 | Dumb Inventions scoring | The -200 missing-chip penalty is removed. Each vote pays `scalePayout(1000, N)` (1000 at 3-4, 750 at 5, 600 at 6) and skipping a chip only forfeits the chip credit the pitch would otherwise show; a player with zero votes scores 0 and can never go negative. `results()` reports standings plus `votesReceived` and `chipsUsed` (0-2 chips per round). | Brief 4 explicitly removes the penalty; the payout is the brief's per-vote figure, and chip usage stays visible as a reveal/stat rather than a score penalty. |
| 2026-11-06 | Dumb Inventions cap | One player's round gain is capped at `MAX_ROUND_SCORE` (1500) only from five players up. 3 and 4 players keep the uncapped per-vote total (2000 at 3, 3000 at 4), identical to the pre-change game. | The human's hard rule requires 3- and 4-player totals to stay identical to before, so 3-4 parity wins over the literal 1500 bound; the cap starts at five players, where the uncapped stacked formula pays 3000. |
| 2026-11-06 | Dumb Inventions privacy | Product names and pitches are withheld from the TV screen state (blanked in `inventions`, and no `options` ballot list) until the reveal phase; during invent and vote the TV gets only the roster, the problem/chip challenge, scores and `waitingOn`. Phones still receive the product names they must vote on. | Brief 1.2 and 3.5 forbid other players' answers reaching the shared screen before the reveal; progress and the waiting list keep the TV alive without leaking submitted text. |
| 2026-11-06 | Bracket range | Bracket Brawl is 3-6 players, ideal 4-6. Catalog `scale()` reports 2 rounds at 3-4 players and 1 round at 5-6, in both standalone and Rumble; write/vote/reveal timers stay 60/20/9 seconds. | Brief 4 gives 3-6 / 4-6 and "one full bracket"; keeping two brackets at 3-4 preserves the old game and its totals, while 5-6 use the extra opening round the larger table needs. |
| 2026-11-06 | Bracket seeding | The bracket is padded to `nextPowerOfTwo(N)`. Byes are placed one per first-round pair (the only arrangement where nobody sits out more than one round); remaining slots are filled with a `secureShuffle` of the seats, so byes and the draw are random. `buildBracket(N, order?)` stays pure: the default order is the seat order (so tests can pin 3- and 4-player fixtures) and the game passes the shuffled order. Slots keep the existing convention: `>= 0` is an entry, `< 0` is the winner of match `(-slot - 1)`. Byes are not matches; the entry appears directly in the next round, so it advances with no vote. | Brief 4 asks for a power-of-two bracket with secure-random byes and at most one bye per player; a pure builder plus an explicit order keeps the general case testable without `Math.random` in the module. |
| 2026-11-06 | Bracket scoring | Duel wins still pay 500, the final 1000, and every voter who backed the winner 100 (fixed, no `f(N)`). From five players up one player's gain in a round is capped at `MAX_ROUND_SCORE` (1500); 3 and 4 players keep the old uncapped totals. `results()` reports standings plus `duelWins` and `votesCorrect` per player. | Brief 3.3's round bound needs the cap at 5-6 (an opening-round winner can otherwise take 2000+), but the human's hard rule keeps 3-4 identical to before: a 4-player semi winner who also backs the parallel semi and wins the final still earns the full 1600. 3-4 parity therefore wins over the literal bound, and the cap starts at five. |
| 2026-11-06 | Stowaway range | Stowaway is 3-8 players, ideal 4-8. Catalog `scale()` reports standalone 3 rounds and Rumble 2 at every count, with brief/clue/discuss/vote/catch/reveal timers unchanged at 6/45/30/20/20/8 seconds; the option caps are one ballot slot per seat plus six category choices. The standalone start runs 3 rounds until the Rumble passes a mode or round count into `onStart`. | Brief 4 gives 3-8 / 4-8 and 3 / 2 rounds; Phase 5's Rumble plumbing is what selects the shorter count at start. |
| 2026-11-06 | Stowaway clue cap | Each clue is sanitised on the server: control characters become spaces, whitespace collapses, punctuation-only tokens are dropped, and at most three words survive (each word also capped at 20 characters). A clue with no usable word is rejected rather than stored. The phone placeholder and info read "three words max" instead of a character count. | Brief 4 caps a clue at 3 words; a word count is the rule players are told, and sanitising server-side means a modified client cannot put a paragraph on the TV. |
| 2026-11-06 | Stowaway rotation | The Stowaway seat is `round % N` (`stowawayFor`), deterministic and never random, so no seat repeats until every player has been the Stowaway once per cycle. Round 1 now initialises through the same `stowBegin` path as later rounds, so the category, six category choices and the rotating seat exist from the first clue. | `round % N` gives an even, predictable rotation for 3-8 players without `Math.random`, and the shared begin path removes the old empty-category first round. |
| 2026-11-06 | Stowaway scoring | Correct voters each get `scalePayout(500, N)` (500 exactly at 3-4, 375/300/250/214 at 5-8). An uncaught Stowaway takes a fixed 1000 and a caught Stowaway takes a fixed 500 for naming the category. The maximum single-round gain is therefore 1000, inside the 1500 bound. `results()` reports standings plus `correctAccusations` for every vote that named the real Stowaway and `roundsUndetected` for each escaped round. | Brief 4 fixes the per-vote scaling, the fixed 1000 and the fixed 500; only the per-vote part passes through `f(N)`, and the two award stats map to Sharpest Eye and Master of Disguise. |
| 2026-11-06 | Stowaway TV privacy | The screen state hides `category`, `stowawayName` and `reveal` (which carries the accused seat) until the reveal phase. Clues and the TV ballot appear only from the discussion onward, so eight clues and eight letter-badged options use the shared 7-9 two-column layout. The catch-guess phase stays silent on the TV. | Brief 3.5 and 3.8 forbid leaking roles, secret words or the accusation before the reveal; the catch guess must not announce who was caught. |
| 2026-11-06 | Fakin' range | Fakin' It is 3-8 players, ideal 4-8. Catalog `scale()` reports standalone 5 rounds and Rumble 3 at every count, with act/vote/reveal timers unchanged at 25/20/8 seconds and one ballot option per other seat (7 at 8 players); the standalone start now runs 5 rounds. | Brief 4 gives 3-8 / 4-8 and 5 / 3 rounds; the catalog owns the target while Phase 5's Rumble plumbing selects the shorter count at start. |
| 2026-11-06 | Fakin' rotation | The Faker order is a `secureShuffle` permutation of every seat, drawn fresh each time the previous cycle is spent and consumed in order, so no seat repeats until every player has been Faker once. Round 1 initialises through the same `fakinBegin` path as later rounds, and `round % N` is gone. | Brief 4 requires a secure-random rotation with no repeats inside a cycle; shuffling a whole cycle gives that guarantee while keeping the draw unpredictable, and the shared begin path removes the old uninitialised first round. |
| 2026-11-06 | Fakin' scoring | Correct voters get `scalePayout(200, N)` (200 exactly at 3-4, 150/120/100/86 at 5-8); an uncaught Faker takes a fixed 500. Catching now follows the brief and `GAMES.md`: more than half of the ballots cast must name the Faker, so a tie, a split or a mere plurality never catches them. At 3-4 players every non-tied unique top is also a majority, so those totals are unchanged. Voters score nothing when the Faker escapes. `results()` reports standings plus `correctVotes` for every vote that named the real Faker and `roundsUndetected` for the Faker. The maximum single-round gain is 500, inside the 1500 bound. | Brief 4 fixes the per-vote figure, the fixed 500 and the strict-majority rule that the code did not implement; only the per-vote part passes through `f(N)`, and the two stats feed Sharpest Eye and Master of Disguise. |
| 2026-11-06 | Fakin' TV privacy | The screen state carries `fakerName`, `reveal` and the vote counts only from the reveal. `waitingOn` lists every player without a vote yet, including the Faker, because filtering them out would name them by omission. All eight seats get a TV option row, so 7+ seats use the shared two-column letter layout. | Brief 3.5 and 3.8 forbid leaking a role or the tally before the reveal; including the Faker in the waiting list closes the inference hole, and the ballot closes the moment the last real voter votes. |
